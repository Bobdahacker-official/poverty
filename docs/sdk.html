DEVELOPER SDK

Make an app.
Make it yours.

The SDK provides the native C API, startup code, runtime, linker script, command-line tools and a working example. Applications run in ring 3 on Avalanche Kernel.

Set up your tools

Install Python 3, an x86-64 GCC toolchain, binutils and OpenSSL. Linux and Windows with WSL can use the same commands. Download and extract the SDK archive, then add its bin directory to PATH.

tar -xzf magenta-sdk.tar.gz
export PATH="$PWD/magenta-sdk/bin:$PATH"
mgnta init hello
mgnta build hello

The result is hello/build/hello.mgnta. Project settings live in hello/magenta.json; add C source files to its sources list.

Your first program

#include <magenta/app.h>

int main(void) {
    mg_write("Hello from Magenta!\n");
    return 0;
}

The build compiles freestanding x86-64 C, links the startup code and runtime, and produces an ELF64 executable at the native application address. CC and LD select alternate compilers and linkers.

The native API

Include <magenta/app.h>. Calls return negative error codes on failure. Memory addresses passed to the kernel belong to the calling process.

AreaFunctions
Terminalmg_write, mg_readline
Filesmg_read, mg_save, mg_remove, mg_mkdir, mg_copy, mg_rename
Processesmg_spawn, mg_wait, mg_kill, mg_pid, mg_task
Systemmg_status, mg_ticks, mg_sleep, av_random
Networkingmg_dns, mg_tcp_connect, mg_tcp_send, mg_tcp_receive, mg_tcp_close, send_u, av_recv
Audioav_audio_play, av_audio_status, av_audio_stop

Ticks run at 100 Hz. File read and write calls transfer up to 65,536 bytes. TCP calls transfer up to 4096 bytes, and the receive timeout is measured in ticks, up to 1000. mg_task returns 1 for a populated process slot and 0 for an empty slot; the process table has 256 slots. See the header for the exact argument types.

Sign with your own key

Create a developer identity once. Keep private.pem on your development machine. Share the certificate and its fingerprint with people who install your apps.

mgnta keygen --out keys --identity "My developer name"

sign hello/build/hello.mgnta \
  --key keys/private.pem \
  --certificate keys/certificate.pem \
  --version 1.0.0 --out signed

mgnta verify signed/hello.mgnta.manifest \
  --certificate signed/trust.der

Signing uses RSA PKCS#1 v1.5 with SHA-256. Key generation creates a 3072-bit RSA key. The manifest records the name, version, dependency, executable filename and SHA-256. Its detached signature is verified against the developer’s certificate. Changing the manifest or executable breaks verification.

The output folder contains the executable, manifest, signature, DER certificate and a ready-to-upload hello.mgnta.zip bundle. Executable payloads hold up to 65,536 bytes. Application names use 1–21 lowercase letters, digits, hyphens or underscores and begin with a letter.

Upload and install

  1. In noVNC, select Upload app.
  2. Choose signed/hello.mgnta.zip. Upload and verify.
  3. Compare the displayed certificate fingerprint with your developer identity.
  4. In Magenta’s Packages app, trust the uploaded signer and install the uploaded app.
  5. Run hello.mgnta in Terminal or open it in Files.

To host a repository yourself, serve the signed folder over HTTP or HTTPS. In Magenta, pin the signing certificate and fetch the manifest. The Packages app’s upload bridge address is editable so it can point to the machine serving your bundles.

A small, open format

.mgnta files are native x86-64 ELF executables. The extension identifies Magenta applications while keeping the executable inspectable with standard tools such as readelf and objdump.

readelf -h hello/build/hello.mgnta
objdump -d hello/build/hello.mgnta

A signed bundle contains exactly four files: the executable, its manifest, its detached signature and trust.der. The upload service checks the archive paths and member sizes, verifies the signature and SHA-256, then publishes the verified bundle for the OS package manager. The OS repeats signature and digest verification before installation.
